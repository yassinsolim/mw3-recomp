# Switches

The runtime is configured through `MW2_*` environment variables. A flag is on
when set to anything but empty or `0` (`runtime/env.h`).

## The settings file

A file named `.env` beside the executables (in the current directory for a
development run) holds switches as `NAME=value`, one a line. The runtime reads
it first thing (`runtime/settings.cpp`) and sets each `MW2_` switch the
environment does not already have, so a variable given on the command line
decides. The launcher writes its own settings there (FULLSCREEN is
`MW2_FULLSCREEN`, ASPECT RATIO and RESOLUTION are `MW2_RENDER` and `MW2_SCALE`, STRETCH is `MW2_STRETCH`, ANTIALIASING is `MW2_MSAA` or
`MW2_NO_MSAA`, ANISOTROPY is `MW2_ANISOTROPY`, SHADOWS is `MW2_SHADOW_SCALE`, FPS LIMIT is `MW2_FPS_LIMIT`, FOV is `MW2_FOV`, CUSTOM MAPS is `MW2_CUSTOM_MAPS`) and keeps the other lines. When the
file has no `MW2_FPS_LIMIT`, the launcher writes the screen's refresh rate as
it opens (60 for a 60 Hz screen, which is the console's pacing). `MW2_LAUNCHER_SOUNDS=0`, written there
by hand, keeps the launcher's own menus silent. `MW2_PC_GAME=<folder>` is the PC game's folder, whose
pictures and sounds ADD MAP gives a converted map (MAPS → PC GAME chooses it). When `.env` has no such line,
the launcher looks for Steam's copy once a run and writes the line when it finds one; an empty
`MW2_PC_GAME=` says there is none. The environment's value decides over the file's
([maps.md](maps.md#inputs)).

A switch is read once, at the start of a run. The Android app's in-game menu
gives six of them another value under a running title, without writing the
environment (`runtime/live_options.h`, [android.md](android.md#the-menu-over-the-game-gamemenukt)):
`MW2_FPS_LIMIT`, `MW2_SHADOWS`, `MW2_FOV`, `MW2_LOD_BIAS`,
`MW2_TEXTURE_BUDGET_MB` and `MW2_SHARPEN`.

Switches marked **R** are read by every build. The rest are diagnostic: a build
without diagnostics (`RELEASE=1 ./build.sh`, `-DMW2_DIAGNOSTICS=OFF`) treats
them as unset whatever the environment says, and also drops the keys `F5`, `F7`,
`F9`, `F10` and `F11`, `kill -USR2` and the end-of-run reports.

## Running

| switch | | effect |
|---|---|---|
| `MW2_WINDOW=0\|1` | R | the window, which every build opens; `MW2_WINDOW=0` keeps it shut, for a headless run. Closing it ends the run as `MW2_RUN_SECONDS` does, with the reports. The frame keeps its proportions in any window shape |
| `MW2_FULLSCREEN=1` | R | starts fullscreen, borderless at the desktop's resolution. `F8` toggles it |
| `MW2_STRETCH=1` | R | the frame fills the window or screen whatever their shapes, instead of keeping its proportions between black bars: for a TV that shows a widescreen signal at 4:3, with a 4:3 frame (`MW2_RENDER`) |
| `MW2_MOUSE=0` | R | Windows: the window does not hold the mouse and the game does not read it. Without it the window holds the mouse while it has the keyboard and the player is in the world -- the cursor hidden and kept inside, the mouse the first player's right stick and triggers, its wheel the weapon switch -- and `F2` or leaving the window (`Alt+Tab`) lets it go; `F2` again, a click in the window or coming back takes it again. With a menu up its buttons are A and B and its wheel the d-pad, and in Modern Warfare 3 the cursor is free and points: what is under it has the focus ([runtime.md](runtime.md#the-mouse)) |
| `MW2_MOUSE_SENSITIVITY=<n>` | R | Windows: how far the mouse turns the view, as the PC game's `sensitivity` (0.022 degrees a count each). Default 5: a thousand counts turn the view 110 degrees. The title's own Sensitivity option multiplies it, and a sight's zoom scales it down ([runtime.md](runtime.md#the-mouse)) |
| `MW2_LOG_FILE=<path>` | R | writes the log there, creating its folder. The log goes to stderr, so `> file` does not catch it. A title started from the other one's menus writes on in the same file |
| `MW2_REPORT=1` | R | what a bug report needs, as the launcher's REPORT A BUG sets it: the log names the graphics driver and ends with the run's frame rate, frame time spread, the share of frames in play that came within 1.05 and within 2.05 of the display's period after the one before, what was compiled at a draw, how much of the time the graphics chip was at work by its own clock (a timestamp pair around every submission), and the processor and memory in play: how busy, how much of it this game's and which threads, how much memory was free, what the memory watch's protection changes cost ([building.md](building.md)) |
| `MW2_REPORT_SECONDS=1` | R | with `MW2_REPORT=1`: a `report: second <n>:` line for each second of play -- its frames, how many of them came on time, the longest, and a frame's time on the graphics chip and on the renderer's thread (with its waits for the chip, its texture reads and its compiling), where the scene is drawn smaller under load the share of its width it was last drawn at, its draws, segments and the constants, vertex data and indices copied for them, and how long after the renderer finished it a frame was presented and was on screen -- so a level's slow places can be found and put down to the chip or the thread |
| `MW2_FOLLOW_DISPLAY=0` | R | the guest's blank keeps its own 60 Hz timer where it would follow the display's ([rendering.md](rendering.md#presenting)): what following is worth, measured by the report's `in play, a frame was presented ... after the renderer finished it, and was on screen ... after` |
| `MW2_LOG_TIME=1` | | stamps every log line with the time since start |
| `MW2_LOG_ALL=1` | | writes every line as it comes. Without it a line that repeats is written once and then counted -- the 1st, 2nd, 4th, 8th ... with the size of the repetition beside it, which is never above the truth and within a factor of two of it -- and two lines that differ only in an address, a size or a shader hash are one kind of line. A run that logs one thing a thousand times buries the line that says what it was |
| `MW2_CONSOLE="30:map af_caves;45:god"` | R | queues commands into the title's console command buffer at the given wall-clock seconds; see [gameplay.md](gameplay.md) |
| `MW2_CUSTOM_MAPS=1` | R | the multiplayer loads fastfiles nobody signed: a map converted from the PC game. Off, it refuses them as the console does, and the launcher's shader pass reads only the game's own fastfiles ([gameplay.md](gameplay.md)) |
| `MW2_DLC_DIR=<folder>[;<folder>...]` | R | where a title's content packages are looked for besides the `dlc` folder beside the game folder: the player's own map packs, Advanced Warfare's install disc's packages and its title update, each folder searched six levels deep ([dlc.md](dlc.md)) |
| `MW2_MOD_DIR=<folder>` | R | Modern Warfare 3: the mods folder, instead of `mods/` in the game folder: one folder per mod, on when `mods.txt` there names it ([mods.md](mods.md)). The same folder is laid over the game's read-only devices |
| `MW2_SCRIPT_DUMP=<folder>` | R | Modern Warfare 3: every script of the game's own that a level loads is written there as source, by its path, for reading or for a mod to start from ([mods.md](mods.md)) |
| `MW2_TRACE_MODS=1` | R | Modern Warfare 3: logs each script and raw file the game asks its asset database for, once: the paths a mod's file can stand for |
| `MW2_UNLOCK_ALL=1` | R | Modern Warfare 3's multiplayer: every weapon, attachment, camouflage (Marine and Winter too), reticle, proficiency, perk, piece of equipment, death streak, strike package streak, title and emblem reads as unlocked, and the menus list fifteen custom classes. The title's own unlock checks and the menus' reads of the stats are answered, and nothing is written to the stats, so without it the menus show what was earned again. Prestige Mode and its shop are left as earned. The Android app's "Unlock all camos and items" sets it and is on by default; unset on the desktop ([MW3-MP-BRINGUP.md](MW3-MP-BRINGUP.md#everything-unlocked)). Advanced Warfare's multiplayer: the item check of `mp/unlocktable.csv` answers unlocked, which matters under Xbox LIVE only; the app's "Unlock all items" sets it, on by default ([AW-BRINGUP.md](AW-BRINGUP.md#what-was-changed)) |
| `MW2_TRACE_UNLOCKS=1` | R | diagnostics builds, Modern Warfare 3's multiplayer: logs every unlock question the title asks (a row of `mp/unlocktable.csv`, a bit of the profile, a menu's or the script's `getPlayerData` path) and what the title itself answers, each once: how a menu that still shows a padlock is traced to its check |
| `MW2_CUSTOM_CAMOS=0` | R | Modern Warfare 3's multiplayer only: the camouflage packs in the game folder's `camos` are not listed in Create a Class, and Gold is drawn as Gold. Unset, every pack there is listed below Gold, each camouflage with its own name, preview and description, chosen per class and weapon and drawn on the weapon in a match; the choices are kept in `saves/custom_camos.txt` and only Gold is written to the stats. One pack is left out, or animated, by `camos/options.txt`, which the Android app's Camo packs screen writes. The log names each pack read and what the weapons wear ([textures.md](textures.md#camouflage-packs)) |
| `MW2_BOTS=<0-17>` | R | The multiplayer of Modern Warfare 3, of Modern Warfare 2's disc version (not its title update 6) and of Call of Duty 4 (0 to 23 there: its server has 24 slots): that many bots join every match this copy hosts and leave when a player needs the slot; nothing happens in a match somebody else hosts. They pick a team and a class through the stock menus, shoot at enemies they can see and walk towards the nearest one, feeling their way round walls (the maps have no path data). The Android launcher's Bots entry and Settings → Multiplayer set it, and the app's pause menu changes it in a match. In a match the host's console takes `bots <n>`, `bots +`, `bots -` and `bots skill <0-3>` (through `MW2_CONSOLE` too) (`runtime/bots.cpp`) |
| `MW2_BOT_SKILL=<0-3>` | R | how well the bots shoot: 0 Recruit, 1 Regular (the default), 2 Hardened, 3 Veteran. It sets their reaction time (600 to 120 ms), aim error (5° to 0.5°), turn rate, view cone, and whether they strafe and crouch in a fight |
| `MW2_BOT_TEAMS=against` | R | every bot joins the side the players are not on. Unset, they are auto-assigned and fill both teams |
| `MW2_MATCH_GRAVITY=<50-3000>` | R | Modern Warfare 3's multiplayer only, as every `MW2_MATCH_` switch: the gravity of the matches this copy hosts, 800 being the title's. Nothing happens in a match somebody else hosts. The server stores it in each player's state, which it sends, so every player predicts with it, a console's included. The Android app's "Match options" set these; in a match the host's console takes `match gravity <n>`, `match speed <percent>`, `match jump <n>`, `match sprint <0\|1>`, `match falldamage <0\|1>`, and `match` alone to log them (through `MW2_CONSOLE` too). The log names the options at every level this copy hosts ([MW3-MP-BRINGUP.md](MW3-MP-BRINGUP.md#match-options), `runtime/match_options.cpp`) |
| `MW2_MATCH_SPEED=<25-400>` | R | movement speed in percent of the title's, on top of what the scripts give a player (a Juggernaut stays slower than the others); sent to every player the same way |
| `MW2_MATCH_JUMP=<10-1000>` | R | the jump height in the title's units, 39 being its own. The title does not send it: this port's host tells this port's players, who then jump alike, and a console in the match predicts 39 and is corrected by the next snapshot. A height that would hurt on landing wants `MW2_MATCH_FALL_DAMAGE=0` |
| `MW2_MATCH_SPRINT=1` | R | sprinting never runs out: every player in the host's matches has the title's own marathon perk |
| `MW2_MATCH_FALL_DAMAGE=0` | R | a fall does no damage in the host's matches |
| `MW2_CUT_MODE=arena\|oneflag\|gtnw` | R | Modern Warfare 3's multiplayer: the matches this copy starts from the System Link or split-screen menu are one of the game modes whose script is on the disc with no menu entry and no rules of its own. They were left unfinished; the lobby and the loading screen still name the mode Game Setup chose. The disc's other two, `ctfpro` and `vip`, do not start and are refused |
| `MW2_MAP_VOTE=1` | R | Modern Warfare 3's multiplayer only: a System Link or private match this copy hosts ends in a vote for the next map, which then loads with every player and bot still in the match instead of everyone being sent back to a menu. Three maps with a game type each appear in the message feed as the match ends, and a player picks one with his tactical grenade, use or lethal grenade button (LB, X, RB on a pad); the vote closes when all have answered or the scoreboard is over, and chance settles a tie or no answer. Nothing happens in a match somebody else hosts. End Game in the host's pause menu ends the match as before. The Android app's "Vote for the next map after my matches" sets it ([multiplayer.md](multiplayer.md#the-next-map)) |
| `MW2_MAP_ROTATION=<map>[:<game type>],...` | R | the maps to go through in order after each match this copy hosts, by fastfile name (`mp_dome:dom,mp_seatown`); a map without a game type keeps the one being played. With `MW2_MAP_VOTE` these are what a vote offers, three of them at a time |
| `MW2_MAP_VOTE_MODES=<game type>,...` | R | the game types a vote draws from (`war,dom,conf`); unset, every one the menus list. The first choice always keeps the game type just played when that is allowed |
| `MW2_MAP_VOTE_SECONDS=<5-60>` | R | the longest a vote stays open (20) |
| `MW2_NET_LINK=0\|1` | R | whether the Ethernet link is reported up. Default down for the campaign, up for MW2's multiplayer, which starts no match without one, and for MW3's multiplayer up when an online service started |
| `MW2_NO_AUTO_SAVE_DEVICE=1` | R | leaves the save-device choice to the title's prompt instead of choosing the hard disk ([saves.md](saves.md)) |
| `MW2_NO_CHECKPOINT_WRITE=1` | R | Advanced Warfare's campaign: a checkpoint is written to the save only by the pause menu's Save and Quit, as on the console. Unset, it is written as soon as the title commits it, so Resume Game goes on from it after the app was closed any other way ([saves.md](saves.md#advanced-warfares-checkpoints)) |
| `MW2_NO_AUDIO=1` | R | opens no playback device; the mixer and decoder still run ([audio.md](audio.md)) |
| `MW2_AUDIO_DUMP=<file.wav>` | | writes the title's mix as it is handed to the output (six channels of 32-bit floats, 48 kHz) to a WAV file: whether a run nobody listened to had sound, and what kind (diagnostic) |
| `MW2_TRACE_MOVIES=1` | | a cutscene's picture and sound on one clock: a log line for every Bink movie opened (size, length, rate), every picture the title steps past (its number, when, and how long its decode took), every sixteenth mixer frame (its number, which is its place in `MW2_AUDIO_DUMP`'s file, when it was submitted, what the output's queue and the device hold ahead of it, and the underruns so far), and every read of a movie's or a streamed sound's file or one that took 20 ms and more (how much, and how long it took). The movie's own sound track found in the dump says which mixer frame belongs to which picture; mixer frames counted against the clock say how far the title's sound has fallen behind (diagnostic) |
| `MW2_RUN_SECONDS=<n>` | | reports and exits after n seconds |
| `MW2_WATCHDOG=<seconds>` | | when it fires: the `MW2_DUMP` blocks, what every guest thread is blocked on (handle and caller) or spinning on, and every thread's backtrace, which is the guest call stack; then exits |
| `MW2_DEBUG_CRASH_AT=<step>` | | writes through a null pointer when start-up reaches that step (the word of a `step:` line of the log: `image`, `guest-memory`, `vulkan-device`, `arena`, ...), to check on a device that a crash that early is reported whole: the step, the signal and the backtrace in `game.log`, and on Android the system's tombstone in the log share ([android.md](android.md#what-the-log-share-holds)). Does nothing unless set to a step's name |
| `kill -USR2 <pid>` | | every thread's stack, as the watchdog prints them, and the run continues (Linux). Sent a few times, it tells a stuck thread from a looping one |
| `MW2_INPUT_SCRIPT="20:start,26:a"` | | presses pad inputs at wall-clock seconds. An entry names a button (`a b x y lb rb start back up down left right lthumb rthumb`), a trigger (`lt`, `rt`) or a stick direction (`lx+ lx- ly+ ly- rx+ rx- ry+ ry-`), with an optional hold time: `"40:lt:25"` holds the left trigger 25 s. Default hold 0.2 s. A name ending in `@2`, `@3` or `@4` is that player's controller, which the script then stands in for: `"5:a@2"`. `guide` is the Guide button, which opens the sign-in screen. On Windows `at<x>/<y>` rests the first player's mouse pointer at that part of the frame while a menu is up (`"30:at0.25/0.2:1"`: a quarter of the way across, a fifth of the way down, for a second) `click` holds its left button, and `turn<dx>/<dy>` moves the mouse that many counts to the right and downwards, evenly over the hold time (`"80:turn1000/0:1"`), with no window in front and no hand |
| `MW2_INPUT_LIVE=<file>` | | a script written while the game runs: the file is read ten times a second from where the last read ended, and each new line is an `MW2_INPUT_SCRIPT` whose times count from the moment it is read (`0:ly+:3,1:a`). A line starting with `!` is a console command (`!viewpos`). For driving a level by looking at the dumped frames between lines, which fixed times cannot do |

## Moving the player

Diagnostic. The multiplayer refuses `setviewpos`, so a spot is reached by
walking to it.

| switch | effect |
|---|---|
| `MW2_WALK_TO="x,y[,radius[,yaw]]"` | walks to a point and holds there, facing the yaw given or turning slowly; reports the closest approach and how often it got itself unstuck |
| `MW2_WALK_PATH=<file>[,<file>...]` | walks a recorded route (`x y z yaw pitch` per line), looking where the player looked; with several, the one starting nearest the spawn. A line `left x y z yaw pitch` or `fire x y z yaw pitch` goes to the spot, turns to the aim, and presses d-pad left or the right trigger there |
| `MW2_TEAM_UP=1\|2` | on the team selection, taps Up that many times before choosing, instead of Auto-assign, so a run spawns on the same side every time |
| `MW2_WALK_REACH=<units>` | how near a route's point the walk has to come before heading for the next: 24 for a point recorded with its view, 140 for the older routes that stop at yaw |
| `MW2_WALK_PAUSE=<seconds>` | stands still at every corner of the route |
| `MW2_QUIT_AFTER_ARRIVAL=<seconds>` | ends the run that long after the walk arrives, or after it stops getting nearer for `MW2_QUIT_IF_STUCK` seconds (45) |
| `MW2_RECORD_FLIGHT=<file>` | writes where the camera is and when, twenty times a second, as a flight for `MW2_FLY_PATH`; noclip and all |
| `MW2_FLY_PATH=<file>` | replays a recorded flight by placing the camera with `setviewpos`, at the same moments counted from the first frame with a player; campaign only, and `MW2_QUIT_AFTER_ARRIVAL` counts from its end |
| `MW2_RECORD_PATH=<file>` | writes where the player goes as a route for `MW2_WALK_PATH`, a point every `MW2_RECORD_SPACING` units (110), with d-pad left and right-trigger presses and their aim |
| `MW2_F5=<command>` | with the window open, `F5` runs that console command: `MW2_F5=noclip` after `devmap`, to fly once a level's opening is behind |
| `MW2_TRACE_VIEWPOS=1` | logs where the player stands once a second |
| `F9` | with the window open and `MW2_ENGINE_LOG=1`: runs the title's `viewpos` and logs the position, whose five numbers `setviewpos x y z yaw pitch` takes in single player |

## The guest

| switch | effect |
|---|---|
| `MW2_TRACE_INDIRECT` | CMake option, on by default: reports an indirect call with no recompiled target instead of jumping to null (one outside the code section is reported in every build) |
| `MW2_ENGINE_LOG=1` | the title's own `Com_Printf` output in the log |
| `MW2_TRACE_ERRORS=1` | the guest call stack under every `Com_Error`; one wrapper raises every error, so the message alone does not say where it came from |
| `MW2_TRACE_CBUF=1` | every command queued to the title's console, which shows what a menu runs (Modern Warfare 2, and Modern Warfare 3's multiplayer) |
| `MW2_TRACE_BOTS=1` | the bots: the menus' names, each menu answer, where every bot is and what it is doing every five seconds, and each target that went down while a bot fired at it |
| `MW2_TRACE_MATCH=1` | Modern Warfare 3's multiplayer, on the host: at every landing, how long the player was in the air, how high it rose, how fast it was moving, which way it faced, how far down it looked and where it landed -- what the `MW2_MATCH_` options and `MW2_FOV`'s turn rate come to, and where a player stands |
| `MW2_TRACE_AIM=1` | Advanced Warfare's multiplayer as the disc has it (not the title update's): the held weapon's times from its asset (sprint in and out, aim in, aim in from a sprint, aim out), every frame of an aim down the sight with the player state's clock, the weapon state and the fraction, and a line with how long the aim took and how far it was when the sprint's end was over; `aim:` lines ([AW-BRINGUP.md](AW-BRINGUP.md#the-aim-after-a-sprint-26-november-2026)) |
| `MW2_TRACE_POINTER=1` | Windows, Modern Warfare 3: each menu the mouse points in, with the items that can be chosen and their rectangles on the frame, and every item the pointer gives the focus |
| `MW2_TRACE_UPDATE_TEXT=1` | Advanced Warfare with a title update of another language than the disc: every string that only the update has, and each one shown in the update's language ([dlc.md](dlc.md#why-the-title-update-and-how-it-is-used)) |
| `MW2_TRACE_FILES=1` | every file opened, read and written. The files asked for and not found are listed at exit regardless |
| `MW2_TRACE_XMA=1` | every XMA decoder kick with its buffers, and FFmpeg's log |
| `MW2_DUMP=<hex>[:words][,...]` | blocks of guest memory to print when the watchdog fires (16 words by default) |
| `MW2_WATCH=<hex>[:bytes]` | a write watchpoint (Linux): the page is made read-only, and every guest write into the range is reported with its call stack and thread, up to `MW2_WATCH_REPORTS` (20); the command processor's writes there are reported too. It logs when it gives up on a busy page |

## Drawing

| switch | | effect |
|---|---|---|
| `MW2_SCALE=<2 or 3>` | R | draws every surface that many times wider and taller than the title's: a 2560x1440 or 3840x2160 frame from the console's 1280x720. The launcher's RESOLUTION entry sets it in the settings file ([rendering.md](rendering.md#resolution-scale)) |
